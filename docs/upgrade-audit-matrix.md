## 7. 执行方式与通过标准

1. **顺序**：M6 静态审计（半天）→ M1/M2 纯代码测试（1~2 天，CI 可跑）→ M5 映射补测试（1 天）→ M3/M4 真实环境（`.12` 流水 3~5 天）
2. **每格证据**：测试名 + 输出、或 `.12` 的 task id + 截图；写回本表「结果」列，并在 `progress.md` 记录批次
3. **失败处理**：任一格失败 → 停止后续矩阵 → 记录根因 → 修复后**从该格重跑**（M3 场景格必须从干净基线重来）
4. **通过标准**：**894** 格全部为 ✅，且 M5 无「未覆盖且未评估」项，才允许在发布材料写「升级功能完整验证」
