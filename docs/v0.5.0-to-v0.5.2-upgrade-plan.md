# v0.5.0 -> v0.5.2 Upgrade Plan

This document is the source of truth for the v2 in-place upgrade chain from
`v0.5.0` to `v0.5.2`. The key rule is that project/network migration is a
separate step from the `v0.5.1u2` bridge package.

## Upgrade Chain

```text
v0.5.0 + runner v0.3.0
  -> v0.5.1u2 + runner v0.3.0
  -> v0.5.1u2 + runner v0.3.1 bootstrap
  -> v0.5.2 + runner v0.3.1
```

`v0.5.1` sites follow the same path starting from the first bridge package:

```text
v0.5.1 + runner v0.3.0
  -> v0.5.1u2 + runner v0.3.0
  -> v0.5.1u2 + runner v0.3.1 bootstrap
  -> v0.5.2 + runner v0.3.1
```

## Compose State Matrix

| Node | Platform | Runner | Compose project | Network name | Subnet | Platform services | Runner service | Prometheus |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Source | `v0.5.0` or `v0.5.1` | `v0.3.0` | `smartx-storage-forecast` | `smartx-storage-forecast_smartx-net` | `10.249.249.0/24` | old project | old project | old project |
| Bridge | `v0.5.1u2` | `v0.3.0` | `smartx-storage-forecast` | `smartx-storage-forecast_smartx-net` | `10.249.249.0/24` | old project | old project | old project |
| Runner bootstrap | `v0.5.1u2` | `v0.3.1` | `smartx-hci-capacity-insight` | `smartx-hci-capacity-insight-net` | `10.249.251.0/24` | stays old project | new project only | stays old project |
| Target | `v0.5.2` | `v0.3.1` | `smartx-hci-capacity-insight` | `smartx-hci-capacity-insight-net` | `10.249.251.0/24` | new project | new project | migrated by v0.5.2 plan only |

## Node 1: Source Runtime

This is the starting state for a `v0.5.0` or `v0.5.1` site.

```yaml
name: smartx-storage-forecast

services:
  web-api:
    image: nazawsze/smartx-hci-capacity-insight-web-api:v0.5.0
    environment:
      SMARTX_COMPOSE_PROJECT_NAME: smartx-storage-forecast

  collector-worker:
    image: nazawsze/smartx-hci-capacity-insight-collector-worker:v0.5.0

  frontend:
    image: nazawsze/smartx-hci-capacity-insight-frontend:v0.5.0

  upgrade-runner:
    image: nazawsze/smartx-hci-capacity-insight-upgrade-runner:v0.3.0
    environment:
      SMARTX_COMPOSE_PROJECT_NAME: smartx-storage-forecast

  prometheus:
    image: prom/prometheus:v2.55.1

networks:
  smartx-net:
    name: smartx-storage-forecast_smartx-net
    ipam:
      config:
        - subnet: 10.249.249.0/24
```

For a `v0.5.1` source site, only the three platform image tags are `v0.5.1`.
The project name, network name, subnet, Prometheus image, and runner image stay
the same.

## Node 2: v0.5.1u2 Bridge Runtime

`v0.5.1u2` is a bridge package. It must not introduce the new project name or
the new network name.

```yaml
name: smartx-storage-forecast

services:
  web-api:
    image: nazawsze/smartx-hci-capacity-insight-web-api:v0.5.1u2
    environment:
      SMARTX_COMPOSE_PROJECT_NAME: smartx-storage-forecast

  collector-worker:
    image: nazawsze/smartx-hci-capacity-insight-collector-worker:v0.5.1u2

  frontend:
    image: nazawsze/smartx-hci-capacity-insight-frontend:v0.5.1u2

  upgrade-runner:
    image: nazawsze/smartx-hci-capacity-insight-upgrade-runner:v0.3.0
    environment:
      SMARTX_COMPOSE_PROJECT_NAME: smartx-storage-forecast

  prometheus:
    image: prom/prometheus:v2.55.1

networks:
  smartx-net:
    name: smartx-storage-forecast_smartx-net
    ipam:
      config:
        - subnet: 10.249.249.0/24
```

The `v0.5.1u2` package requirements are:

| Item | Required value |
| --- | --- |
| `package_type` | `platform` |
| platform images | `web-api`, `collector-worker`, `frontend` only |
| runner image | must not be included |
| Prometheus image | must not be included |
| `minimum_runner_version` | must not be present |
| `database_migration` | `false` |
| migration payload | must not be present |
| environment transition payload | must not be present |
| required capabilities | `backup.create`, `image.load`, `files.sync`, `compose.override`, `compose.apply`, `health.http`, `rollback.restore` |
| project compose files | must use `smartx-storage-forecast` and `smartx-storage-forecast_smartx-net` |

## Node 3: Runner v0.3.1 Bootstrap Runtime

Runner bootstrap is the first step that introduces the new project and network,
but only for `upgrade-runner`.

```yaml
name: smartx-hci-capacity-insight

services:
  upgrade-runner:
    image: nazawsze/smartx-hci-capacity-insight-upgrade-runner:v0.3.1
    command: ["python", "-m", "app.upgrade_runner.main"]
    environment:
      SMARTX_COMPOSE_PROJECT_NAME: smartx-hci-capacity-insight
      SMARTX_PROJECT_PATH: /opt/smartx-storage-forecast
      SMARTX_COMPOSE_FILE: docker-compose.release.yml
      SMARTX_DB_PATH: /data/smartx.db
      SMARTX_PROMETHEUS_DATA_PATH: /prometheus-data
      SMARTX_HOST_PROJECT_PATH: /opt/smartx-storage-forecast
      SMARTX_HOST_COMPOSE_RUNTIME_PATH: /data/compose-runtime
    volumes:
      - /opt/smartx-storage-forecast:/opt/smartx-storage-forecast
      - /data:/data
      - /data/upgrades:/data/upgrades
      - /data/backups:/data/backups
      - /data/exports:/data/exports
      - /data/compose-runtime:/data/compose-runtime
      - /prometheus-data:/prometheus-data
      - /var/run/docker.sock:/var/run/docker.sock
    networks:
      - smartx-net

networks:
  smartx-net:
    name: smartx-hci-capacity-insight-net
    ipam:
      config:
        - subnet: 10.249.251.0/24
```

Expected runtime after this step:

```text
old project smartx-storage-forecast:
  web-api v0.5.1u2
  collector-worker v0.5.1u2
  frontend v0.5.1u2
  prometheus v2.55.1
  upgrade-runner v0.3.0 may remain only until cutover policy removes it

new project smartx-hci-capacity-insight:
  upgrade-runner v0.3.1
```

Runner bootstrap must not restart or migrate `web-api`, `collector-worker`,
`frontend`, or `prometheus`.

## Node 4: v0.5.2 Target Runtime

`v0.5.2` is the platform migration step. This is where the platform services
move to the new project and network.

```yaml
name: smartx-hci-capacity-insight

services:
  web-api:
    image: nazawsze/smartx-hci-capacity-insight-web-api:v0.5.2
    environment:
      SMARTX_COMPOSE_PROJECT_NAME: smartx-hci-capacity-insight

  collector-worker:
    image: nazawsze/smartx-hci-capacity-insight-collector-worker:v0.5.2

  frontend:
    image: nazawsze/smartx-hci-capacity-insight-frontend:v0.5.2

  upgrade-runner:
    image: nazawsze/smartx-hci-capacity-insight-upgrade-runner:v0.3.1
    environment:
      SMARTX_COMPOSE_PROJECT_NAME: smartx-hci-capacity-insight

  prometheus:
    image: prom/prometheus:v2.55.1

networks:
  smartx-net:
    name: smartx-hci-capacity-insight-net
    ipam:
      config:
        - subnet: 10.249.251.0/24
```

Prometheus movement belongs to the `v0.5.2` migration design. It must not happen
in `v0.5.1u2` or in runner bootstrap.

## Package Build Gates

Before a package is accepted, inspect its `manifest.json` and packaged compose
files.

### v0.5.1u2 Gates

```bash
tar -xOf smartx-capacity-insight-upgrade-v0.5.1u2.tar.gz manifest.json | python3 -m json.tool
tar -xOf smartx-capacity-insight-upgrade-v0.5.1u2.tar.gz project/docker-compose.release.yml | grep -E '^(name:|    name:|        - subnet:|      SMARTX_COMPOSE_PROJECT_NAME:)'
```

Expected:

```text
name: smartx-storage-forecast
SMARTX_COMPOSE_PROJECT_NAME: smartx-storage-forecast
name: smartx-storage-forecast_smartx-net
subnet: 10.249.249.0/24
```

Rejected values in `v0.5.1u2`:

```text
name: smartx-hci-capacity-insight
name: smartx-hci-capacity-insight-net
subnet: 10.249.251.0/24
required_capabilities: backup.v1/image.v1/files.v1/compose.v1/health.v1/rollback.v1
minimum_runner_version
environment_transitions
migration or migration_steps
images/upgrade-runner.tar
```

### Runner v0.3.1 Bootstrap Gates

Expected:

```text
package_type: component
component: upgrade-runner

bootstrap_runner.enabled: true

bootstrap_runner.target_network: smartx-hci-capacity-insight-net
```

The package must contain only the runner image and must not contain platform or

## Known Failure Pattern

If `v0.5.1u2` contains the new project/network compose files, platform restart
fails with:

```text
failed to create network smartx-hci-capacity-insight-net:
invalid pool request: Pool overlaps with other one on this address space
```

This means the bridge package incorrectly attempted the v0.5.2 project/network
migration early. Rebuild `v0.5.1u2` with old project/network compose files.
