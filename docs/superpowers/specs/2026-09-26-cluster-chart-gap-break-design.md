# 集群容量趋势图：断档处断开实际容量曲线 + 只画到真实采集数据

- 日期：2026-09-26
- 状态：已实施并验证（2026-09-26，.3 前端 tsc 0 / vitest 103 passed，后端 350 tests OK；提交待用户批准）
- 关联任务：task_plan.md Phase 49 第 41 条；pending-tasks #35
- 触发：用户反馈「集群容量趋势（实际容量、预测趋势与容量阈值）图表里，如果没收集到数据，实际使用容量应该断开」

## 1. 背景与根因

1. 图表横轴是**类目轴**，类目只包含"有数据的日期"（后端 `clusters[].points` 的日粒度点）。
2. 类目相邻 ⇒ ECharts 直接连线：2026-08-20 与 2026-09-12 两个点会被画成一条平滑斜线，看起来像这两周有连续数据。
3. `.3` 实际序列：`08-12~08-20` 有样本 → `08-21~09-11` 断裂 → `09-12~09-18` 平坦 → `09-26` 回填写入。图表把断裂处连了起来。
4. 另外图表序列仍来自"从现在回算"的查询，会把快照回填产生的**假点**（当前时间戳、旧值）画在最后。

## 2. 口径

- 实际容量曲线**只在有真实采集数据的日期之间连线**；没有数据的日期填 `null`，曲线在该处断开（ECharts `connectNulls` 默认 false）。
- 后端图表序列（`clusters[].points`）**只取到最后一次成功采集**（口径同 49-39），不再画回填/暂停期的假点；`当日容量` 标记与未来预测因此锚定在最后一次真实采集值上。
- 「历史预测」「未来预测」「预测上下限」「告警阈值」「存储卷有效容量」保持连续（它们是模型/常量线，不是实测曲线）。

### 2.1 边界（不做）

- 不改图表范围切换（7/30/90/365 天）、状态徽标、图例与配色（沿用 `#0f9fbf` 等既有色）。
- 不改后端 `forecast`/`slope`/band 的算法，只改其输入端"取哪些样本"。
- 不改看板（Dashboard）的图表。

## 3. 实施方案

1. 前端新增 `frontend/src/services/chartGrid.ts`：`buildDailyGrid(points)` 把稀疏日粒度点补成**连续日序列**，缺失日 `null`。
2. `frontend/src/components/ClusterCapacityChart.tsx`
   - 横轴类目改为 `buildDailyGrid(actualPoints)` 的连续日期；
   - `实际容量使用` 序列按类目取值（缺失为 `null`）→ 断档处断开；
   - `predictedHistory(labels, points, slope)` 改为按连续类目逐点用公式计算（保持连续），替代原来"只在有数据的类目上取值"。
3. 后端 `reports/service.py::_latest_report`：`chart_series` 用 `end_ts=last_success_ts`（无成功采集则为空）。

## 4. 测试计划
