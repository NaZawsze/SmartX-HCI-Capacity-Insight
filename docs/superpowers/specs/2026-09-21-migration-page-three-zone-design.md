# 数据迁移页三区结构重组设计（#26 剩余批次）

状态：已实施（2026-09-21）。设计输入：[2026-09-20-migration-page-ux-review.md](2026-09-20-migration-page-ux-review.md) §6.1（结构重组）/ §8（验收基准）；术语客户化与使用说明卡已在第一/二/三批落地，本批只做结构。

## 目标

不看文档的新用户能从界面直接回答：导出会得到什么、两种导出差别、两种导入差别、导入后还要做什么。

## 结构（原单卡+头部按钮 → 三张分区卡）

1. **导出区**（第一卡，主路径）：
   - 主按钮「导出迁移包」+ 说明「包含 Tower 配置与全部历史数据」；成功后在卡内常驻显示「恢复需要两份文件」成对保存引导（迁移包 + 恢复密钥，任务中心附下载链接）。
   - 「仅导出 Tower 配置」降级为卡内次要入口（说明：不带历史数据，供新环境快速接入 Tower）。
   - 头部三个按钮全部撤除（健康检查并入环境状态区）。
2. **导入区**（第二卡）：
   - 导入方式由同名 toggle 改为**可选卡片**（radio group）：「合并数据（默认）——只补缺的，现有数据不动」/「整库替换——清空并替换现有数据」，替换卡选中态红色边框 + 后果行红色强调；确认勾选、导入前自动备份说明不变。
   - 底部提示条固定「导入完成后需执行服务重启」+ 新增「去服务重启」按钮（onNavigate 直达，导入完成后最显眼的下一步）。
3. **环境状态区**（第三卡，健康检查常驻化）：
   - 进入页面自动执行一次只读体检（GET /api/admin/migration/health，不改数据），常驻展示：业务库（在/不在 + 表数量）、历史指标（block 数）、完整性（完整/不完整 + message）。
   - 「健康检查」降级为「重新检查」刷新按钮；检查失败/请求失败同样常驻展示。

## 边界（不变）

- .env 不进迁移包、0600、下载需密码确认（第三批已实现）；导出双路径与后端接口零改动（无路由/契约变更，api.md 不动）。
- 覆盖导入未勾选确认不可触发（前端禁用 + 后端 400 双保险）。
- 导入不自动重启服务（重启是独立显式动作）。
- 文件名保持机器可读，展示层翻译为客户语言。
