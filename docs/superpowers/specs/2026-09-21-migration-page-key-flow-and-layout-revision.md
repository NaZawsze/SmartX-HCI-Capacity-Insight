# 数据迁移页修订：导出按钮回右侧 / 使用说明字体 / 导出后密钥确认弹窗

状态：设计稿（2026-09-21），对 [2026-09-21-migration-page-three-zone-design.md](2026-09-21-migration-page-three-zone-design.md) 三区结构重组（提交 d50651c）的三项用户反馈修订。

来源（用户反馈原话，2026-09-21，附迁移页截图）：

> 1. 你这里导出迁移包和仅导出 Tower 配置怎么跑左边来了，不如上一版右边好看。
> 2. 字体大小有问题。
> 3. 导出迁移包自动下载密钥，那你下载密钥需要验证密码还有什么意义呢？去掉导出迁移包自动下载密钥，并且点击导出迁移包后弹窗提示需要下载恢复密钥，并提供下载恢复密钥按钮和取消，下载恢复密钥按钮点击后需要进行输入密码才允许下载才对。

## 1. 背景与现状核对

三区重组后（d50651c），迁移页结构：

- `PageHeader`（无 action）。
- 导出迁移包区：卡头「导出迁移包」+ 描述，卡内 `.migration-export-actions` **左对齐**放「导出迁移包」(primary) 和「仅导出 Tower 配置」(secondary)。
- 迁移包导入区：上传 + 两张模式卡片（合并数据 / 整库替换）+ 服务重启提示。
- 环境状态区：自动体检 + 「重新检查」按钮 + 业务库 / 历史指标 / 完整性三行。
- 使用说明区：裸 `<strong>使用说明</strong>`（15px）+ `<ul>`（13px）+ 底部「下载恢复密钥」按钮行。
- 底部「下载恢复密钥」密码弹窗（`keyDialogOpen`，输入平台登录密码 → `POST /api/admin/migration/env-file` 下载当前 `.env`）。

现状问题（对应三条反馈）：

1. **导出按钮位置**：重组把两个导出按钮从 `PageHeader` 的 `action`（右侧）挪到导出卡内左侧，用户明确更喜欢上一版右侧布局。
2. **使用说明字体**：`使用说明` 标题是裸 `<strong>`（15px），与其余三张卡的 `.service-operation-head` 标题（继承 16px）不一致；且无卡头底部分隔线，视觉上与四区其它卡不统一。
3. **密钥流程自相矛盾**：导出成功后行内提示「恢复密钥（已自动生成，任务中心可下载）」——密钥被"自动给出"；而「下载恢复密钥」按钮又要输密码。用户逻辑：既然导出就自动给密钥了，密码门控就没意义。要把"下载密钥"变成导出后**显式、需密码**的一步。

## 2. 修订设计

### 2.1 导出按钮回右侧（PageHeader action）

- `PageHeader` 恢复 `action`，放 `.service-header-actions.service-migration-actions` 两个按钮：
  - 「仅导出 Tower 配置」(secondary，`Download` 15)
  - 「导出迁移包」(primary，`Download` 16)
- 删除导出卡内的 `.migration-export-actions` 块。导出卡保留卡头（标题+描述）与导出后的结果提示（见 2.3）。
- 「健康检查/重新检查」保持在环境状态区（三区设计的刻意改动，用户未异议），不进头部。

### 2.2 使用说明字体统一

- `使用说明` 卡头改成与其它三区一致的 `.service-operation-head`：`<div><strong>使用说明</strong><span>迁移包、恢复密钥与导入操作的说明，按需参考。</span></div>`。标题回到 16px（继承），带底部分隔线，四卡视觉统一。
- `.service-migration-guide > strong` 规则删除（改由 `.service-operation-head strong` 统一）。
- `<ul>` 正文 13px 保持不变（与其它卡正文一致）。

### 2.3 导出后密钥确认弹窗（核心）

流程改为（用户指定的交互）：

1. 点「导出迁移包」→ 打包并浏览器下载迁移包（不变）。
2. 导出成功后**弹出密钥确认弹窗**（`exportKeyPrompt`），文案：迁移包已下载，恢复需要"恢复密钥"；密钥不打进包里、需单独下载保存。两个按钮：
   - **「下载恢复密钥」**（primary）→ 打开既有密码弹窗（`keyDialogOpen`），需输入平台登录密码验证后才真正下载。
   - **「取消」**（secondary）→ 关闭提示。
3. 密码弹窗「确认下载」→ `POST /api/admin/migration/env-file` 下载当前 `.env`（`project.env`），成功后提示「已下载恢复密钥」。

配套调整：

- 删除 `exportPairedNotice` 行内提示（"已自动生成，任务中心可下载"的表述正是用户认为"密码门控没意义"的根源），改为上述弹窗。
- `keyDialogOpen` 增加"由导出弹窗触发"语义：密码弹窗标题/文案保持通用（「下载恢复密钥」），既可由导出弹窗进入，也可由页底「下载恢复密钥」按钮直接进入（保留页底常驻入口）。
- 密码弹窗下载成功后：若由导出弹窗触发，则同时关闭 `exportKeyPrompt`；`exportMessage` 置为「已下载恢复密钥，请与迁移包一起保存。」
- 导出失败不弹密钥确认弹窗。
- 仅导出 Tower 配置：不弹密钥确认弹窗（配置包体积小、用途是快速接入，维持现状的 `exportMessage` 提示即可）。

### 2.4 后端保持不变（范围说明）

- `_snapshot_env_for_bundle`（导出时在服务器 `exports/migrations/` 留档一份与包同名的 `.env` 配对快照 + 任务中心下载链接）**保留**。理由：这是服务器侧留档与任务中心可追溯能力，不是浏览器自动下载；用户反馈针对的是前端"自动给出密钥 + 行内提示"的表述与流程，不是要删除服务器留档。
- `POST /api/admin/migration/env-file`（密码门控下载当前 `.env`）不变，继续作为密钥下载的唯一通道。
- 无路由/契约变更，`scripts/verify_api_docs.py` 不受影响。

## 3. 边界与不变项

- `.env` 不进迁移包（密文/钥匙分离）、0600、下载需登录密码（`AuthService.confirm_password`，空/错密码 403）。
- 覆盖导入前强制自动备份 + 确认勾选（不变）。
- 导入不自动重启服务（不变）。
- 前端样式遵循 docs/frontend-style-guide.md：颜色只用 `:root` 变量，6/8px 圆角，弹窗沿用既有 `.modal-backdrop` + 卡片式对话框模式。
