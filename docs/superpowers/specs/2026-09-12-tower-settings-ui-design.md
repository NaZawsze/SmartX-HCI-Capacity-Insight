# Tower 设置页完整 UI 设计（添加/编辑/集群/删除）

更新时间：2026-09-12
状态：设计完成，待实施
关联：task_plan.md Phase 49 第 11 项；继承 [v2-frontend-design.md](../../v2-frontend-design.md) 的 v1 蓝白风格要求；颜色/圆角/组件规格以 [frontend-style-guide.md](../../frontend-style-guide.md) 为准

## 1. 背景与现状问题

当前 Tower 设置页（`SettingsPage.tsx`，2305 行文件的一部分）存在以下问题：

| # | 问题 | 严重度 |
| --- | --- | --- |
| P1 | 删除 Tower 无确认对话框，点击即删，误触不可恢复 | 高 |
| P1 | 创建前无法测试连接：`POST /api/towers/{id}/test` 只接受已创建的 Tower，用户只能"先创建、失败再删" | 高 |
| P2 | 创建表单 11 个字段单列平铺，连接认证、采集策略、安全选项混排，无分组 | 中 |
| P2 | 认证方式（用户名+密码 vs API Token）的互斥关系没有表达，用户不知道填哪个 | 中 |
| P2 | 编辑表单与创建表单是两份几乎相同的 JSX（约 60 行重复），改一处漏一处（采集间隔就只改了两处） | 中 |
| P2 | 集群启停 checkbox 挂在编辑表单最底部，与采集配置混在一起，层级混乱 | 中 |
| P3 | Tower 列表行不显示最近采集时间/结果，用户无法判断 Tower 是否健康 | 低 |
| P3 | 数字输入无边界提示，错误只靠后端 message 兜底，无字段级校验 | 低 |

## 2. 设计原则

- 继承 v1/v2 现有蓝白业务风格（`Card` + `.settings-form` + `.primary-button`），不引入新视觉体系。
- 每个操作有闭环：测试有 loading 与结果反馈，保存有成功/失败提示，删除有确认。
- 表单组件抽取复用：创建与编辑共用 `TowerForm`，差异通过 props 表达（编辑模式密码/Token 留空不改、显示集群分区）。
- 不改变任何后端语义；需要的新后端能力单列为"后端配合项"，接口先行。

- 列表行新增：最近采集状态徽标（成功=绿点+相对时间；失败=黄点+异常；从未采集=灰点"未采集"）。数据源用现有 `towers` 接口扩展（后端配合项 B2）。
- 操作按钮：编辑（进入右列编辑态）、测试连接（行内即时执行，转圈 2s 上限）、删除（弹确认框）。
- 新增入口改为按钮（右列表单默认收起），替代现在常驻的左表单，减少首屏噪音。

## 4. 添加 Tower：向导化分组表单

表单分三个分区（同一卡片内用分区标题分隔，不做多步向导，保持一次提交）：

### 4.1 分区一：连接认证

~~~text
名称*        [________________________]
地址*        [https://__________________]   （占位 https://tower.example.com）
认证方式      (•) 用户名 + 密码     ( ) API Token
─── 认证方式 = 用户名 + 密码 ───
用户名*      [________]
密码*        [________]（type=password）
─── 认证方式 = API Token ────
API Token*   [________]
────────────────────────────
[✓] 校验 TLS 证书（默认勾选，内网自签环境可取消）
[测试连接]  ← 不保存，用当前表单值发起测试；成功显示"连接成功，发现 N 个集群"
~~~

- 认证方式用 radio 切换，未选中的认证输入隐藏并清空——消除"密码和 Token 都填以谁为准"的歧义。
- 地址失焦做 URL 格式校验；非 https 显示黄色提示（不阻断，内网 http 允许）。

### 4.2 分区二：采集策略（用户确认修订：两模式分段切换 + 分区式布局）

用户确认只需要两种调度模式：**每日定时 / 按间隔**（单次采集不做）。

**布局修订（2026-09-12，用户反馈表单凌乱后重新设计）**：整表改为**分区式布局**——编号分区标题 + 单列字段堆叠，功能块归位：

~~~text
┌ 编辑 Tower ────────────────────────────────┐
│ ① 连接信息                                  │
│   名称     [____________________________]  │
│   地址     [____________________________]  │
│   用户名   [____________________________]  │
│   密码     [____________________________]  │
│   API Token [___________________________]  │
│   ☐ 校验 TLS 证书      ☑ 启用采集            │
├────────────────────────────────────────────┤
│ ② 采集计划                                  │
│   采集模式   [ 每日定时 │ 按间隔 ]            │
│   采集间隔   [ 60 ] 分钟                     │
│   ☑ 采集失败重试   间隔[15]分钟  最多[3]次     │
├────────────────────────────────────────────┤
│ ③ 集群 (1)                    [同步集群]     │
│   ☑ SMARTX-TT-WW                            │
├────────────────────────────────────────────┤
│                          [取消]  [保存]      │
└────────────────────────────────────────────┘
~~~

关键规则：

- **每个字段单列堆叠、等宽**，不再两列交错——切换采集模式时只有"采集计划"分区内的一个输入行变化，其余字段纹丝不动。
- **失败重试从认证区移入"② 采集计划"分区**（模式详情行下方），它属于采集策略不属于凭据。
- **校验 TLS / 启用采集移入"① 连接信息"**，不再挂在表单最底部。
- 模式详情行给固定最小高度，两种模式的字段结构一致（一行标签+一行输入），切换不产生布局跳动。
- 创建表单复用相同分区（无③集群、无取消按钮），按钮"创建"。

模式语义：

- `每日定时`：每天固定钟点采集一次，长期循环（time 输入，24 小时制）。
- `按间隔`：按 N 分钟周期循环采集，不看钟点（默认 60 = 每小时一次）。
- `towers.collection_mode TEXT`（`interval` / `daily`，迁移按旧 interval_minutes 是否为 0 回填）；worker 调度同步按模式生成触发器：daily→cron(hour, minute)；interval→interval（分钟 <=0 回落 60）。

### 4.3 底部操作

~~~text
[测试连接]（次要按钮，重复出现于此便于提交前最后验证）
[创建]（主按钮；loading 期间禁用并显示"创建中"）
```

字段级校验失败时在对应输入下方显示红色小字；提交按钮可点击但后端 422 时滚动到首个错误字段。

### 4.4 字段规格

| 字段 | 必填 | 校验 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| 名称 | 是 | 1~64 字符，去除首尾空格 | 空 | 列表与侧栏显示名 |
| 地址 | 是 | URL 格式；接受带端口 | 空 | CloudTower 基地址 |
| 认证方式 | 是 | radio | 用户名+密码 | 决定提交 username/password 或 api_token |
| 用户名/密码 | 认证方式=密码时必填 | 非空 | 空 | |
| API Token | 认证方式=Token 时必填 | 非空 | 空 | |
| 校验 TLS 证书 | - | - | 勾选 | |
| 采集间隔 | - | 0~10080 整数 | 60 | 0=每日一次 |
| 每日采集时间 | 间隔=0 时必填 | time | 02:10 | 仅每日模式生效 |
| 重试间隔/次数 | - | 1~1440 / 0~10 | 15 / 3 | 沿用现有语义 |

## 5. 编辑 Tower

- 复用同一 `TowerForm`（`mode="edit"`），分区与创建一致，差异：
  - 密码/API Token 显示占位"留空则不修改"，留空提交时字段不出现在 payload（现有 `normalizeTowerUpdatePayload` 语义保留）。
  - 认证方式初始值按 Tower 已存凭据类型推断；切换方式且新凭据填写后按新方式提交。
  - 表单顶部显示只读上下文：`CHINATOWER · https://10.20.0.6:5443 · 最近采集 12 分钟前（成功）`。
- 编辑态切换时若表单有改动，切换/关闭前弹"放弃更改？"确认（对比表单快照）。

## 6. 集群分区（编辑表单内独立分区）

~~~text
─── 集群（N）───   [同步集群]
[✓] SMARTX-TT-WW    最近样本 11:17（成功）
[✓] CLUSTER-B       最近样本 —（未采集）
~~~

- 从编辑表单底部移到独立分区，每行：启用 checkbox + 集群名 + 最近样本时间/状态。
- "同步集群"按钮调用现有 `POST /api/towers/{id}/clusters/sync`，完成后刷新列表并 toast 新增/移除数量。
- 切换启用立即生效（现有 `updateCluster` 语义），开关操作加 300ms 防抖并显示行内 loading。

## 7. 删除确认

~~~text
┌─ 删除 Tower ────────────────────┐
│ 确认删除 CHINATOWER？              │
│ · 该 Tower 将停止定时采集           │
│ · 已有容量历史与报表记录保留         │
│ · 关联集群配置（N 个）将被删除       │
│              [取消]  [删除]（红色） │
└─────────────────────────────────┘
~~~

- 复用任务中心确认交互样式；删除执行中按钮 loading，失败显示原因。
- 二次防护：输入 Tower 名称方可删除属于增强项，默认不做（内网单管理员场景，确认框已够）。

## 9. 后端配合项

| 编号 | 内容 | 说明 |

| B1 | `POST /api/towers/test`（无 id）：接收临时连接参数（base_url + 认证方式二选一 + verify_tls），返回 `{ok, message, clusters: [...]}` | 支持创建前测试连接；凭据不落盘 |

## 10. 验收标准

- [ ] 创建 Tower 全流程：填表 → 测试连接成功 → 保存 → 列表出现且 5 分钟内出现首次采集记录。
- [ ] 认证方式切换后只提交所选方式的凭据；编辑留空密码不改变现有凭据。
- [ ] 采集间隔与每日时间的联动（置灰/激活）正确；保存后 worker 60s 内按新配置调度。
- [ ] 删除必须经过确认框；取消不产生任何请求。
- [ ] 集群分区同步、启停即时生效。
- [ ] 前端目标测试全绿；`SettingsPage.tsx` 收敛到 800 行以内。
- [ ] 远端 10.20.11.3 构建 + recreate + 健康检查 + 浏览器抽查。

## 11. 不做范围

- 多步向导、拖拽排序、Tower 分组标签。
- 凭据回显（安全边界，密码/Token 永不明文返回）。
- 批量导入 Tower（后续增强单独立项）。
